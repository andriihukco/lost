# Lost MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A mobile-first Next.js PWA where a host creates a room, adds treasures by coordinates or map pin with photos, and friends join by link to see each other and find treasures by GPS distance.

**Architecture:** Next.js App Router (client components for map, geolocation, realtime), Supabase for anonymous auth, Postgres with RLS and two RPCs (`join_room`, `mark_found`), Storage for private photos, Realtime Broadcast for positions and Postgres Changes for found events. Pure logic (distance, coordinate parsing, room codes, image sizing) lives in `src/lib/` and is unit-tested with Vitest.

**Tech Stack:** Next.js (App Router) + TypeScript, Tailwind CSS, `@supabase/supabase-js`, MapLibre GL JS with MapTiler style, Motion, Vitest. Supabase CLI for local migrations and SQL tests. Deploy target: Vercel.

**Spec:** `docs/superpowers/specs/2026-11-14-lost-mvp-design.md` (executors read both; decisions D1–D10 and §15 accepted defaults apply).

## Global Constraints

- Room code alphabet: `abcdefghjkmnpqrstuvwxyz23456789` (31 chars), length 6, stored without hyphen.
- Found radius: `FOUND_RADIUS_M = 15` metres; unlock when `max(0, distance − accuracy) ≤ 15`.
- Photo max side: 1200 px; output WebP, falling back to JPEG.
- Photo bucket `treasure-photos` is private; signed URLs expire after 3600 s; path `{room_id}/{treasure_id}/{n}.webp`.
- Position broadcast: at most once per 2–3 s, only when moved more than 2 m. Marker fades to 40% opacity after 30 s without update.
- Viewport: `viewport-fit=cover`; map height `100dvh`; never `user-scalable=no`.
- All inputs `font-size: 16px` minimum.
- `navigator.vibrate` is optional (no-op on iOS).
- Source files ≤ 400 lines.
- UI copy in Ukrainian; exact action labels ("Додати на карту", "Підтвердити знахідку", "Скопіювати посилання").
- No commits or pushes except as stated in Task 1 (initial `git init` and commit only after the user approves this plan).

## Review Focus

1. **Decimal-comma coordinates** (`49,8419, 24,0315`), common in Ukrainian locale. Expected: parsed correctly, not rejected or split into four numbers. Pinned by Task 3.
2. **Out-of-range or single-number input** (`91, 24`, `49.8`, empty). Expected: `null`, form shows an error, no save. Pinned by Task 3.
3. **Missing or zero GPS accuracy** (`accuracy` undefined, NaN, negative). Expected: no compensation, so the 15 m rule applies strictly. Pinned by Task 2.
4. **Concurrent "Found" taps** on one treasure. Expected: exactly one winner, the other gets `taken`. Pinned by Task 6 verification.
5. **Unknown or mistyped room code** (`/r/abc12`, `/r/xxxxxx`). Expected: a clear "Кімнату не знайдено" page, no crash, no enumeration. Pinned by Task 6 (`join_room` returns null) and Task 9.

### Task 6: Database schema, RLS, and RPCs

**Files:**
- Create: `supabase/migrations/0001_init.sql`, `supabase/tests/found_race.sh`
- Modify: none

**Interfaces:**
- Consumes: none
- Produces:
  - Tables `rooms`, `treasures`, `participants` as in spec §5, with `treasures.photo_paths text[]`, `treasures.found_by uuid`, and no `found_count` or `found_by_name` (decisions D1, D2, D3). PostGIS not enabled.
  - `rpc join_room(p_code text) returns rooms` (SECURITY DEFINER, `set search_path = public`). Returns the room row or null. Does not return the room to non-members except through this function.
  - `rpc mark_found(p_treasure_id uuid) returns jsonb` returning `{ "status": "won" | "taken" | "not_member", "found_by": uuid | null }`.
  - Storage bucket `treasure-photos`, private.

- [ ] **Step 1: Write the migration**

Write tables, `check` constraints from spec §5, RLS enabled on all three tables. Policies:
- `rooms` select: participant of that room.
- `participants` select: participant of the same room; insert: `user_id = auth.uid()`; update own nickname and colour.
- `treasures` select: participant of the room; insert, update, delete: `rooms.host_id = auth.uid()`.
- Storage: read signed URLs only for objects under `{room_id}` where the caller is a participant; write only for the room host.

The core of `mark_found` is the single conditional statement, which the rest of the function wraps:

```sql
update treasures set is_found = true, found_by = auth.uid(), found_at = now()
where id = p_treasure_id and is_found = false
  and room_id in (select room_id from participants where user_id = auth.uid())
returning room_id;
```

If zero rows are returned, the function checks whether the treasure exists and is found (`taken`) or the caller is not a member (`not_member`). If the update succeeded, it sets `rooms.status = 'finished'` when no unfound treasures remain.
